# Зберігання та відновлення у власному акаунті

1. Cloud plugin, незалежний private GitHub/Drive backup, локальна установка й робочі проєкти — різні шари. Втрата ноутбука не повинна втрачати єдину source-копію; доступ/MFA до хмар відновлюється окремо із захищеного сховища.
2. Після дозволеної зміни зберегти повний versioned ZIP, manifest/SHA256, ліцензії, external receipt і LATEST у погоджених приватних destinations. Звірити source readback, ZIP paths/types/CRC, download/hash та owner-only permissions. Старі копії залишити. Не називати автоматичним backup без чинного перевіреного runner; не створювати credentials/автосинхронізацію без дозволу.
3. На новому комп'ютері взяти одну незалежну копію, перевірити trusted SHA256 і безпечну структуру до extraction/execution, розпакувати у нову папку. Потрібен Python 3.10+ standard library для original offline diagram CLI та перевірок. Native engines не потрібні для базових SVG/draw.io/BPMN exports. Зовнішні plugins/tools та власна авторизація — окремо й лише за потребою.
4. Через підтримуваний Plugin Creator створити власний приватний plugin із цього clean ZIP або встановити `skills/workflow-portable` у фактичний каталог local skills клієнта. Типовий Codex каталог — `$CODEX_HOME/skills` або `~/.codex/skills`. Існуючу однойменну установку спочатку порівняти й зберегти, не перезаписувати без review. Cache вручну не редагувати.
5. Відкрити новий сеанс і перевірити фактично loaded skill path та одну безпечну задачу. Якщо host вимагає restart, погодити його окремо; активні чати/SSH не закривати. Локальні перевірки не доводять cloud/desktop discovery або доступ до всіх зовнішніх сервісів.
6. Проєктні журнали, код, БД, документи, чати, credentials і binaries мають власний backup; цей пакет їх не містить. Для передачі далі знову зібрати clean allowlist, перевірити licenses/provenance/history, видалити свої preferences/IDs/дані. Ніколи не відкривати весь приватний backup repo. Нікому не надсилати пакет без прямого доручення.
