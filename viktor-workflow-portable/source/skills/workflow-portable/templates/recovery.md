# Зберігання та відновлення у власному акаунті

1. Хмарний плагін, незалежний приватний резерв GitHub/Drive, локальне встановлення й робочі проєкти — різні шари. Втрата комп’ютера не повинна знищити єдину копію джерел; доступ і MFA до хмар відновлюються окремо із захищеного сховища.
2. Після дозволеної зміни зберегти повний версійний ZIP, маніфест і SHA256, ліцензії, зовнішній підсумковий запис і LATEST у погоджених приватних місцях. Перевірити зворотне читання джерел, шляхи, типи файлів, CRC, завантаження, контрольні суми й доступ лише власника. Старі копії залишити. Не називати резервування автоматичним без чинного перевіреного виконавця; доступи чи автосинхронізацію без дозволу не створювати.
3. На новому комп’ютері взяти незалежну копію, звірити довірену SHA256 і безпечну структуру до розпакування або виконання, розпакувати в нову папку. Для перевірок і оригінального засобу діаграм потрібен Python 3.10+ зі стандартною бібліотекою. Сторонні засоби не потрібні для базових експортів SVG/draw.io/BPMN. Зовнішні плагіни, інструменти та власна авторизація — окремо й за потребою.
4. Через підтримуваний Plugin Creator створити власний приватний плагін з очищеного ZIP або встановити `skills/workflow-portable` у фактичний каталог локальних навичок клієнта. Типовий каталог Codex — `$CODEX_HOME/skills` або `~/.codex/skills`. Наявну однойменну установку спочатку порівняти й зберегти; без перевірки не перезаписувати. Кеш вручну не редагувати.
5. Відкрити новий сеанс і перевірити фактично завантажений шлях навички й одну безпечну задачу. Якщо клієнт потребує перезапуску, погодити його окремо; активні чати та SSH не закривати. Локальні тести не доводять виявлення навички хмарним або настільним клієнтом чи доступу до всіх зовнішніх сервісів.
6. Проєктні журнали, код, БД, документи, чати, облікові дані й виконувані файли мають власне резервування; цей пакет їх не містить. Перед поширенням знову скласти очищений дозволений перелік, перевірити ліцензії, походження та історію, прибрати особисті налаштування, ідентифікатори й дані. Не відкривати весь приватний репозиторій резервів. Не надсилати пакет іншим без прямого доручення.
